# Round 033 — Generative NaN cycle memory: controlled progress

## Goal
Make the 256-vertex/32,640-pair memory useful in **generation** instead of only static classification. Round 033 implements two independently tested modules, using WordNet 3.1 noun definitions:

1. A **byte-level autoregressive generator** with a 24-channel trainable cyclic memory readout versus an exactly matched plain-memory control.
2. A **learned episodic retrieval-and-copy generator** with unseen WordNet lemmas and two-character query corruption, whose answer bytes are stored and read from the **actual 8 MiB C++ mirror root** via three-edge triangle circulations.

This is a hybrid research prototype, **not a fluent language model**. The two components have separate training loops; the native episodic copy reader is not differentiated end-to-end through the byte LM. The episodic decoder emits an already stored 24-byte answer via hard-copy selection and is not capable of synthesizing unseen prose. A conventional indexed copy system obtains identical accuracy.

## Input data and provenance
WordNet source: `/mnt/data/nan_round025/corpus.jsonl` (from supplied WordNet 3.1 archive). The code references this path in `experiment.py`. Change `CORPUS` to your extracted corpus location. Original training source is not duplicated in the archive.

The autoregressive experiment selects up to 1,800 random noun glosses per preexisting train/validation/test split, and applies validation-based checkpoint selection. WordNet's label/category ordering is mitigated by random selection per split, but source-disjoint general language generalization has not been shown.

The episodic experiment uses 3,500 distinct lemma identities per split, removes cross-split duplicates, and selects 12 candidate concepts per episode. A query is corrupted by independently replacing two character positions. The learned key encoder identifies the selected concept; the output is the first 24 bytes of its stored gloss.

## Reproduce
Dependencies: Python 3.10+, NumPy, PyTorch; g++ C++20.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python experiment.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python episodic.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python integration.py
```

The integration script uses three-seed learned checkpoints generated by `episodic.py`; it recompiles `native_episodic.cpp` in that step. All checkpoints and results are bundled.

## Held-out next-byte generative metrics
180 updates, 2 matched seeds, 24 trainable memory coefficients in both variants. Loss = bits per byte (lower better). Samples remain incoherent.

| Seed | Plain bpb | Triangle bpb |
|---|---:|---:|
| 17 | 3.67070 | 3.67077 |
| 29 | 3.67881 | 3.67881 |

There is **no predictive gain** from the current cycle readout. Both models exhibit sensitivity to zeroing memory; the cycle path passes gauge invariance. Scrambling the triangle assembly after training impairs performance, but is a mismatched ablation and is **not** proof of a unique topology benefit.

## Held-out episodic text generation
Three random seeds, 300 independently sampled held-out episodes per seed:

| Seed | Correct selected record = exact 24-byte output |
|---|---:|
| 17 | 300 / 300 |
| 29 | 296 / 300 |
| 41 | 290 / 300 |

The decoder emits the stored bytes from the selected memory, and correctness is equivalent to key-selection accuracy. The query has two corrupted characters and concept identities are absent from training.

## Actual native-root test
120 new held-out episodes evaluated with the seed-17 learned key encoder, with 12 records × 24 bytes each written into anchored triangle coordinates of a **single 8,388,608-byte C++ root** per episode. A random vertex-gauge shift of standard deviation 8 is applied after writing. Results:

- Correct record and exact 24-byte completion: **118/120 (98.33%)**, both before and after the gauge shift.
- Conventional indexed lookup with identical selected record: **118/120 (98.33%)**.
- Raw single-edge value after gauge shift: **94/2880 individual bytes (3.26%)** correct.
- All 288 stored random test bytes recovered exactly after strong gauge shift in the independent native root audit.

No claims of quantum physics. The triangles are classical gauge invariants computed in ordinary RAM. Root lifetime is stable during each episode; unlike Round 024, memory locking (`mlock`) was not requested. In this prototype the episode root is re-instantiated for each test, so per-episode allocation costs are excluded from inference-performance claims.

## Engineering significance and next tests
The cycle invariant preserves memory values despite changes in the vertex reference frame: F(0,a,b) = e(0,a)+e(a,b)-e(0,b). This is *exact* algebraically; residual float errors did not change any copied output bytes under the tested conditions. The root addresses can be used as a stable **gauge-independent write/read transport**.

To improve actual free generation, the next move is to connect this retrieval to the token distribution with an explicit learned **copy gate** and train it jointly with the byte LM, using book-disjoint corpora and matched controls: standard attention memory with equivalent retrieval budget, gauge-aware real-valued memory, and raw pair memory. Real advantages should be established on held-out bits-per-byte, exact facts, latency, and memory, not on a synthetic gauge shift alone.
